# Анализ структуры БД для разработки `ext_alphaSrv`.

### 1. Бизнес-термины ➔ Сущности БД

| Термин из Концепции | Сущность в БД АльфаЦЕНТР | Ключевые таблицы / поля |
| :--- | :--- | :--- |
| Привязка ТУ к УСПД | Группы контроллеров | `gr_kon` (`n_kon`, `n_sh`) |
| `last_data` (Время последних данных) | Состояние опроса | `amr_comm_state` (`n`, `tm` / `logtm`) |
| Интервал опроса | План опроса (основные параметры) | `plan_opr2` (`interv`) | YES |
| Попытки опроса (Retries) | План опроса (основные параметры) | `plan_opr2` (`kol_pop` / `kol_pop_max`) |
| *Конфигурация опроса (Этап 2)* | *Расширенные параметры опроса* | *`param_oprsh2`* |

### 2. Детальный анализ ключевых таблиц для Этапа 1

#### 2.1. Таблица для СВЯЗИ и ФИЛЬТРАЦИИ
*   **`gr_kon`** (Привязка ТУ к контроллеру)
    *   `n_kon` — ID УСПД.
    *   `n_sh` — ID ТУ.
    *   *Роль*: Главная таблица для получения списка всех ТУ, принадлежащих конкретному УСПД (`usp_ids`).

#### 2.2. Таблицы для ЧТЕНИЯ (Анализ `last_data` и текущих настроек)
*   **`amr_comm_state`** (Состояние опроса ТУ)
    *   `n` — предположительно ID ТУ (`n_sh`).
    *   **`tm`** (или `logtm` / `stm`) — временная метка последнего успешного опроса/получения данных. Это и есть наш **`last_data`** из Концепции.
*   **`plan_opr2`** (Основные параметры опроса ТУ)
    *   `n_sh` — ID ТУ.
    *   `interv` — текущий интервал опроса.
    *   `kol_pop` (или `kol_pop_max`) — текущее количество попыток опроса.

#### 2.3. Таблицы для ЗАПИСИ (Обновление параметров на Этапе 1)
*   **`plan_opr2`**
    *   Обновление полей `interv` и `kol_pop` / `kol_pop_max` для переведения ТУ в режим оптимизации или экономии.

### 4. Критические вопросы к предметному эксперту (Перед стартом разработки)

Поскольку мы опираемся на новые таблицы, разработчику **необходимо получить 100% подтверждение** по следующим полям:

1. **Поле `last_data` в `amr_comm_state`**: 
   * В таблице есть поля `tm`, `stm`, `logtm`, `synctm`. Какое именно из них содержит время получения последних *данных* (показаний), которое нужно сравнивать с временным окном (`star_thour` ... `end_hour`)?
2. **Связь `amr_comm_state` и ТУ**: 
   * Поле `n` в `amr_comm_state` — это гарантированно `n_sh` (ID счётчика)?
3. **Поле "Попытки опроса" в `plan_opr2`**: 
   * Что именно нужно обновлять: `kol_pop` или `kol_pop_max`? (Обычно `kol_pop` — это текущее/базовое, а `kol_pop_max` — лимит, но нужно подтверждение).
4. **Единицы измерения `interv` в `plan_opr2`**: 
   * В Концепции (п. 6.1) указано, что `interval_opt` / `interval_econ` задаются в **часах**. В каком формате `plan_opr2.interv` хранит значение в БД (в минутах, часах, секундах)? Потре ли конвертация при записи?
