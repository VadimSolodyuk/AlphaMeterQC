### 2. Детальный анализ ключевых таблиц для Этапа 1

#### 2.1. Таблицы для СВЯЗИ и ФИЛЬТРАЦИИ
*   **`kontr`** (Справочник УСПД)
    *   `n_kon` — ID УСПД (используется для валидации `usp_ids` из конфига).
    *   `txt` — наименование (для логов).
*   **`gr_kon`** (Привязка ТУ к контроллеру)
    *   `n_kon` — ID УСПД.
    *   `n_sh` — ID ТУ.
    *   *Роль*: Главная таблица для получения списка всех ТУ, принадлежащих конкретному УСПД (`usp_ids`).
*   **`sh`** (Справочник ТУ)
    *   `n_sh` — ID ТУ.
    *   `sost` — состояние (в работе / выведен). *Критично: обновлять параметры нужно только для ТУ в активном состоянии.*
    *   `txt` — наименование ТУ (для логов).

#### 2.2. Таблицы для ЧТЕНИЯ (Анализ `last_data` и текущих настроек)
*   **`amr_comm_state`** (Состояние опроса ТУ)
    *   `n` — предположительно ID ТУ (`n_sh`).
    *   **`tm`** (или `logtm` / `stm`) — временная метка последнего успешного опроса/получения данных. Это и есть наш **`last_data`** из Концепции.
*   **`plan_opr2`** (Основные параметры опроса ТУ)
    *   `n_sh` — ID ТУ.
    *   **`interv`** — текущий интервал опроса.
    *   **`kol_pop`** (или `kol_pop_max`) — текущее количество попыток опроса.

#### 2.3. Таблицы для ЗАПИСИ (Обновление параметров на Этапе 1)
*   **`plan_opr2`**
    *   Обновление полей `interv` и `kol_pop` / `kol_pop_max` для переведения ТУ в режим оптимизации или экономии.

### 3. Рекомендуемая SQL-логика для реализации Acceptance Criteria

#### Шаг 1: Проверка существования УСПД (AC-3)
```sql
SELECT n_kon, txt FROM kontr WHERE n_kon = :usp_ids;
-- Если записей 0 -> Логировать ERROR и останавливать службу (AC-3).
```

#### Шаг 2: Получение списка активных ТУ для данного УСПД
```sql
SELECT gk.n_sh, sh.txt, sh.sost 
FROM gr_kon gk
JOIN sh ON gk.n_sh = sh.n_sh
WHERE gk.n_kon = :usp_ids 
  AND sh.sost = 1; -- Только ТУ в активном состоянии
```

#### Шаг 3: Получение `last_data` и текущих параметров опроса
```sql
SELECT 
    po.n_sh, 
    po.interv AS current_interval, 
    po.kol_pop AS current_retries, -- Уточнить у эксперта: kol_pop или kol_pop_max
    acs.tm AS last_data            -- Уточнить у эксперта: tm, logtm или stm
FROM plan_opr2 po
LEFT JOIN amr_comm_state acs ON po.n_sh = acs.n
WHERE po.n_sh IN (:list_of_active_n_sh);
```

#### Шаг 4: Пакетное обновление (Транзакционность)
Согласно п. 6.1 Концепции, изменения применяются пакетно.
```sql
BEGIN TRANSACTION;

-- Обновление для ТУ, которым нужно сменить режим
UPDATE plan_opr2 
SET interv = :new_interval, 
    kol_pop = :new_retries 
WHERE n_sh IN (:list_of_n_sh_to_update);

COMMIT;
```
*После успешного `COMMIT` служба инициирует перезапуск `AlphaSrv` через ОС.*
