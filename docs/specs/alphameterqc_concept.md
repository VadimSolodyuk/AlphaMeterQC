# Концепция приложения AlphaMeterQC

Статус: черновик.

## 1. Назначение и границы первой версии

### 1.1. Назначение

AlphaMeterQC предназначено для контроля наличия и проверки корректности данных о параметрах электросети в цепях учёта электроэнергии, хранящихся в базе данных ПО «АльфаЦЕНТР».

### 1.2. Границы первой версии

Первая версия охватывает один законченный рабочий сценарий: специалист вручную запускает проверку за выбранный период. Приложение получает данные из БД, определяет, какие ожидаемые данные отсутствуют на момент проверки, выполняет применимые проверки параметров электросети и формирует отчёт.

## 3. Проблема и ожидаемая польза

Для проверки корректности параметров электросети цепей учёта электрической энергии специалист оценивает данные по каждому присоединению: наличие напряжений и токов, их соответствие допустимым значениям, согласованность фазовых углов и соответствие токов потреблению электроэнергии.

Проверка повторяется для большого числа присоединений. Она требует сопоставления нескольких групп параметров с учётом схемы подключения и характера нагрузки, поэтому трудоёмка и подвержена риску ошибки. Несколько нарушений могут возникать одновременно.

AlphaMeterQC должно выполнять эти проверки единообразно и показывать, какие данные не поступили, какие отклонения выявлены и какие проверки выполнить не удалось. Результаты проверок оформляются в виде отчёта, состав и вид которого определяются при согласовании требований к первой версии. Специалист использует результат для принятия решения о дальнейших действиях.

Перед согласованием концепции необходимо подтвердить: текущий порядок проверки, объём проверяемых присоединений, получателей результатов и существующие возможности АльфаЦЕНТР.

## 4. Основной сценарий

### 4.1. Запуск приложения на сервере

1. Специалист вручную запускает AlphaMeterQC на сервере ПО «АльфаЦЕНТР».
2. При запуске открывается графический диалог ввода параметров подключения к БД. Специалист использует единую учётную запись. Ранее сохранённые параметры, кроме пароля, подставляются автоматически. Пароль вводится при каждом запуске приложения.
3. После подтверждения ввода приложение получает параметры из диалога и выполняет подключение к БД.
4. Если подключение к БД не удалось, приложение сообщает причину ошибки и предоставляет возможность повторного ввода параметров подключения.
5. После успешного подключения приложение продолжает работу на сервере в качестве системной службы и становится доступным специалистам через веб-интерфейс.

### 4.2. Выполнение проверки

1. Специалист на своём автоматизированном рабочем месте (АРМ) открывает веб-интерфейс приложения и указывает ФИО.
2. Специалист задаёт настройки контроля и запускает проверку. Настройка «Глубина анализа, суток» принимает целые значения от 1 до 31; значение по умолчанию — 1. Начало периода анализа — 00:00:00 календарной даты, предшествующей дате запуска проверки на указанное число суток. Конец периода — дата и время запуска проверки. При глубине 1 анализируются предыдущие календарные сутки и прошедшая часть текущих суток, а не последние 24 часа. Остальные настройки контроля и варианты их выбора в веб-интерфейсе подлежат отдельной проработке.
3. Приложение получает из БД данные, необходимые для анализа, и выполняет применимые проверки по всем доступным измерениям выбранного периода.
4. Приложение отображает результаты проверки в форме отчёта в веб-интерфейсе. Форма предусматривает поле «Примечание» для каждой записи об отклонении.
5. Специалист анализирует результаты и вводит или уточняет примечания.
6. После завершения работы с примечаниями специалист выгружает отчёт в файл электронной таблицы для подписания и направления руководителю отдела.
7. Руководитель определяет мероприятия по устранению выявленных отклонений.

### Записи об отклонениях и примечания

Каждое отклонение оформляется отдельной записью. Ключ записи — присоединение и вид отклонения; номер счётчика указывается справочно. Для нескольких эпизодов одного вида отклонения на одном присоединении состав ключа и связь эпизодов с записями отчёта предстоит уточнить.
Примечание сохраняется при выходе из поля ввода. На время редактирования блокируется только эта запись, а не всё присоединение или отчёт. Другие записи можно редактировать одновременно. Таймаут снятия блокировки при прерванной сессии предстоит определить.

Для сохраняющегося отклонения используется примечание из прошлого отчёта. Как выбирать исходный отчёт, отмечать перенос и учитывать повторное появление отклонения после перерыва, предстоит уточнить.

## 6. Проверки и диагностические правила

### Период анализа и эпизоды отклонений

Приложение анализирует все доступные измерения выбранного периода и выделяет отдельные эпизоды отклонений. Дата и время запуска проверки фиксируются один раз и используются как конец периода анализа и как момент расчёта продолжительности эпизодов без установленного окончания.

Для каждого эпизода указываются:

- Дата и время начала — время первого измерения, в котором обнаружено отклонение.
- Дата и время окончания — время первого последующего измерения, в котором условие отклонения больше не выполняется. Если такого измерения в выбранном периоде нет, поле остаётся пустым; отдельный статус незавершённого эпизода не отображается.
- Продолжительность — разность между временем окончания и временем начала. Если окончание не установлено, продолжительность рассчитывается от начала эпизода до времени запуска проверки, даже если последнее доступное измерение получено раньше. Формат — чч:мм:сс; часы отображаются суммарно, без сброса после 24 часов, например 27:15:00.

Границы эпизода определяются по измерениям и не означают точного физического времени возникновения и прекращения отклонения. Расчёт продолжительности до запуска проверки сам по себе не подтверждает сохранение отклонения после последнего доступного измерения. Повторное возникновение отклонения после его прекращения учитывается как новый эпизод.

Порядок обработки отклонения, уже присутствующего в начале выбранного периода, и пропусков измерений между подтверждениями отклонения предстоит определить отдельно.

### Проверки параметров и диагностика

- Отсутствие измерения отличается от измеренного нулевого напряжения или тока. Нулевой ток сам по себе не считается неисправностью.
- Для счётчиков прямого включения отдельные пороги наличия напряжения и тока не задаются: измеренное ненулевое значение считается наличием. Отклонение напряжения оценивается относительно номинального по общему правилу. Предложенное начальное значение допуска — ±10 %. Применимость порога 0,05 А вторичного тока для счётчиков, включённых через трансформаторы тока, предстоит уточнить.
- Симметрия токов проверяется только при наличии тока во всех трёх фазах. Для присоединений ниже и выше 1 кВ применяется одинаковый критерий: отношение наибольшего фазного тока к наименьшему превышает заданный порог. Предложенное начальное значение порога — 2. Для присоединений ниже 1 кВ проверку можно отключить в веб-интерфейсе; другие проверки при этом сохраняются. Правило для напряжения ровно 1 кВ предстоит определить.
- Если доступные измерения показывают отсутствие тока в части фаз при его наличии в других, симметрия не оценивается. Для присоединений выше 1 кВ фиксируется «Отсутствует ток фазы». Для присоединений ниже 1 кВ при напряжении во всех трёх фазах и токе только в одной допускается предположение «Возможно однофазная нагрузка».
- Сообщения «Возможно однофазное подключение; требуется проверка» для напряжения и тока только в одной фазе и «Ток без напряжения» для тока при измеренном нулевом напряжении той же фазы остаются предложениями.

Допуски и пороги задаются в веб-интерфейсе; их применённые значения указываются в отчёте. Отключённая проверка отмечается как «не выполнялась по настройке», а не как отсутствие отклонений. Предложенные начальные значения не являются нормативным заключением.
