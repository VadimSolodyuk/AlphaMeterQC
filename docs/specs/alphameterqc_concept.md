# Концепция приложения AlphaMeterQC

Статус: черновик.

## 1. Назначение и границы первой версии

### 1.1. Назначение

AlphaMeterQC предназначен для контроля наличия и проверки корректности данных о параметрах электросети в цепях учёта электроэнергии, хранящихся в базе данных ПО «АльфаЦЕНТР».

### 1.2. Границы первой версии

Первая версия охватывает один законченный рабочий сценарий: специалист вручную запускает проверку за выбранный период. Приложение получает данные из БД, определяет, какие ожидаемые данные отсутствуют на момент проверки, выполняет применимые проверки параметров электросети и формирует отчёт.

## 3. Проблема и ожидаемая польза

Для проверки корректности параметров электросети цепей учёта электрической энергии специалист оценивает данные по каждому присоединению: наличие напряжений и токов, их соответствие допустимым значениям, согласованность фазовых углов и соответствие токов потреблению электроэнергии.

Проверка повторяется для большого числа присоединений. Она требует сопоставления нескольких групп параметров с учётом схемы подключения и характера нагрузки, поэтому трудоёмка и подвержена риску ошибки. Несколько нарушений могут возникать одновременно.

Приложение AlphaMeterQC должно выполнять эти проверки единообразно и показывать, какие данные не поступили, какие отклонения выявлены и какие проверки выполнить не удалось. Результаты проверок оформляются в виде отчёта, состав и вид которого определяются при согласовании требований к первой версии. Специалист использует результат для принятия решения о дальнейших действиях.

Перед согласованием концепции необходимо подтвердить: текущий порядок проверки, объём проверяемых присоединений, получателей результатов и существующие возможности АльфаЦЕНТР.

## 4. Основной сценарий

Плановый контроль выполняется ежедневно и запускается специалистом вручную.

1. При ручном запуске инженер вводит пароль единой учётной записи для доступа к БД. При подключении к веб-интерфейсу специалист указывает ФИО.
2. Специалист задаёт число суток N от 1 до 31 (по умолчанию 1). Период начинается в 00:00 дня «сегодня минус N» и заканчивается текущим временем. Специалист выбирает, включать ли счётчики прямого включения.
3. Приложение получает из БД данные о параметрах электросети, номинальное напряжение и тип включения счётчика.
4. Приложение контролирует поступление данных и выполняет применимые проверки по разделу 6.
5. Приложение формирует отчёт, различая обнаруженные факты, диагностические предположения и причины, подтверждённые специалистом.
6. Специалист добавляет или уточняет примечания и направляет отчёт руководителю отдела не реже одного раза в неделю. Руководитель определяет мероприятия по устранению отклонений.

### Записи об отклонениях и примечания

Каждое отклонение оформляется отдельной записью. Ключ записи — присоединение и вид отклонения; номер счётчика указывается справочно. История изменений примечаний не хранится.

Примечание сохраняется при выходе из поля ввода. На время редактирования блокируется только эта запись, а не всё присоединение или отчёт. Другие записи можно редактировать одновременно. Таймаут снятия блокировки при прерванной сессии предстоит определить.

Для сохраняющегося отклонения используется примечание из прошлого отчёта. Как выбирать исходный отчёт, отмечать перенос и учитывать повторное появление отклонения после перерыва, предстоит уточнить.

## 5. Предпосылки и ограничения

- Приложение работает как служба на сервере ПО «АльфаЦЕНТР». Специалисты работают через веб-интерфейс без установки отдельного клиентского ПО.
- Согласование размещения администраторами и службой безопасности принимается за предпосылку; фактическое согласование не подтверждено.
- Служба использует единую учётную запись для доступа к БД; отдельные учётные записи специалистов в БД не требуются. Для сценария нужна только возможность чтения; фактические права предстоит проверить.
- Автоматический запуск службы в первую версию не входит. Введённое ФИО указывает автора, но не подтверждает его личность. Защита передачи пароля и правила его хранения подлежат согласованию.
- Отчёты, записи об отклонениях и настройки общие для специалистов отдела и хранятся в служебных каталогах приложения на том же сервере.

## 6. Проверки и диагностические правила

- Отсутствие измерения отличается от измеренного нулевого напряжения или тока. Нулевой ток сам по себе не считается неисправностью.
- Для счётчиков прямого включения отдельные пороги наличия напряжения и тока не задаются: измеренное ненулевое значение считается наличием. Отклонение напряжения оценивается относительно номинального по общему правилу. Предложенное начальное значение допуска — ±10 %. Применимость порога 0,05 А вторичного тока для счётчиков, включённых через трансформаторы тока, предстоит уточнить.
- Симметрия токов проверяется только при наличии тока во всех трёх фазах. Для присоединений ниже и выше 1 кВ применяется одинаковый критерий: отношение наибольшего фазного тока к наименьшему превышает заданный порог. Предложенное начальное значение порога — 2. Для присоединений ниже 1 кВ проверку можно отключить в веб-интерфейсе; другие проверки при этом сохраняются. Правило для напряжения ровно 1 кВ предстоит определить.
- Если доступные измерения показывают отсутствие тока в части фаз при его наличии в других, симметрия не оценивается. Для присоединений выше 1 кВ фиксируется «Отсутствует ток фазы». Для присоединений ниже 1 кВ при напряжении во всех трёх фазах и токе только в одной допускается предположение «Возможно однофазная нагрузка».
- Сообщения «Возможно однофазное подключение; требуется проверка» для напряжения и тока только в одной фазе и «Ток без напряжения» для тока при измеренном нулевом напряжении той же фазы остаются предложениями.

Допуски и пороги задаются в веб-интерфейсе; их применённые значения указываются в отчёте. Отключённая проверка отмечается как «не выполнялась по настройке», а не как отсутствие отклонений. Предложенные начальные значения не являются нормативным заключением.
