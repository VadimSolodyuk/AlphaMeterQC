# Состояние AlphaMeterQC

Обновлено: 2026-11-05.

## Текущий фокус

[Issue #2 — Переход на GitHub Issues и docs/development/](https://github.com/VadimSolodyuk/AlphaMeterQC/issues/2).

Этап: подготовка изменений профильных AI-ролей в ai-dev-settings.

Согласовано:
- Учёт разработки через GitHub Issues и docs/development/,
  без Stage Output и workflow_registry.
- Правила учёта размещаются в профильных ролях;
  Core не меняется, отдельный workflow.md не создаётся.
- Контекст конкретного поручения формируется из Issue,
  относящихся к нему решений, ограничений и материалов.
  Этот файл используется для навигации и межзадачного контекста,
  а не для обязательной загрузки каждой модели.
- Процесс и инструкции уточняются по результатам практической проверки,
  после согласования изменений.

Новые инструкции ещё не записаны и не проверены в Continue.
Пилот — перенос значимых сведений из docs/temp/
без возобновления разработки ext_alphaSrv.

## Навигация

- [Issue #1 — Упорядочивание проекта](https://github.com/VadimSolodyuk/AlphaMeterQC/issues/1):
  общий план, результаты предыдущих работ и отложенные задачи.
- [Issue #2 — Миграция учёта разработки](https://github.com/VadimSolodyuk/AlphaMeterQC/issues/2):
  границы, план, критерии завершения и результаты текущей работы.

Задачи, существенные решения и результаты ведутся в Issues.
Подробные рабочие материалы — в связанных документах по необходимости.
Параллельные списки задач и копии подробных планов не ведутся.

## Общие ограничения

- Изменения файлов и записи в GitHub — после подтверждения
  точного состава; разрешение инструмента его не заменяет.
- Различать подготовку, согласование, запись, проверку и приёмку.
  Не распространять результаты проверок за проверенный объём.
- Отложенные работы не возобновлять без согласования.
  Ollama и диагностика CI/бинарников не входят в текущую работу.
- До удаления или переноса файлов проверять назначение,
  зависимости, ссылки и сохранность значимых сведений.
