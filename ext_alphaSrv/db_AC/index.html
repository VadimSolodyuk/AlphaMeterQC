2.3. Таблицы для ЗАПИСИ (Обновление параметров на Этапе 1)

place2 (Свойства ТО):

  • id, NUMBER: ID ТО.
  • state, NUMBER (0/1): если 0: данный данная ТО исключается из дальнейшего анализа.
  • connectwait, NUMBER: ожидать соединения (сек.). Необходимое значение: ?????????????????????????.
  • kol_pop, NUMBER: количество попыток соединиться. Необходимое значение в зависимости от режима:
  • econom: 3
  • normal: если есть и валиден JSON:connection_retries: connection_retries, иначе: 5.

plan_opr2 (Общие свойства опроса ТУ/УСПД):

  • place_id, NUMBER: ID ТО.
  • n_sh, NUMBER: ID ТУ/УСПД.
  • interv, VARCHAR(4) (30m, 1h - 12h, 1d, 10d, 1n; где h - час, m - минта, d - день, n - месяц): интервал опроса. Необходимое значение: если значение <= 1h: не меняется, иначе: если есть и валиден JSON:interval: interval, иначе: 8h.
  • kol_pop_max, NUMBER: количество повторов опроса в интервале при неудаче. Необходимое значение в зависимости от режима:
  • econom: 1
  • normal: если interv в часах (h) и > 1: interv - 1, иначе: 1.
  • state, NUMBER (0/1): если 0: данная ТУ исключается из дальнейшего анализа.
  • dorder, NUMBER: порядковый номер в списке опроса. Необходимое значение: 1.
  • pause_retry, NUMBER: пауза перед повтором опроса (сек.). Необходимое значение: interv(сек.) / (kol_pop_max + 1).

gr_kon (Привязка ТУ к контроллеру): - n_kon — ID УСПД - n_sh — ID ТУ. Роль: Главная таблица для получения списка всех ТУ, принадлежащих конкретному УСПД (usp_ids).

2.2. Таблицы для ЧТЕНИЯ (Анализ last_data и текущих настроек)

*   `amr_comm_state` (Состояние опроса ТУ)
*   `n` — предположительно ID ТУ (`n_sh`).
*   `tm` (или `logtm` / `stm`) — временная метка последнего успешного опроса/получения данных. Это и есть наш **`last_data`** из Концепции.
