Анализ структуры БД для разработки ext_alphaSrv

1. Таблицы/поля (Этапе 1)

place2 (Свойства ТО):

  • id, NUMBER - ID ТО.
  • state, NUMBER (0 - вкл.; 1 - откл.) - состояние опроса. Если 0: данная ТО исключается из анализа.
  • connectwait, NUMBER - время ожидания соединения (сек.). Необходимое значение: ?????????????????????????.
  • kol_pop, NUMBER - количество попыток соединиться. Необходимое значение в зависимости от режима:
  • econom: 3
  • normal: если есть и валиден JSON:connection_retries: connection_retries, иначе: 5.
  • advanced: если есть и валиден JSON:connection_retries: connection_retries х 2, иначе: kol_pop х 2.

plan_opr2 (Общие свойства опроса ПУ или УСПД):

  • place_id, NUMBER - ID ТО.
  • n_sh, NUMBER - ID ПУ или УСПД.
  • interv, VARCHAR(4) (30m, 1h - 12h, 1d, 10d, 1n; где h - час, m - минта, d - день, n - месяц) - интервал опроса. Необходимое значение: если значение <= 1h: не меняется, иначе: если есть и валиден JSON:interval_amr: interval_amr, иначе: 8h.
  • kol_pop_max, NUMBER - количество повторов опроса в интервале при неудаче. Необходимое значение в зависимости от режима:
  • econom: 1
  • normal: если interv в часах (h) и > 1: interv - 1, иначе: 1.
  • state, NUMBER (0 - вкл.; 1 - откл.) - состояние опроса. Если 0: ПУ|УСПД исключается из анализа.
  • dorder, NUMBER - порядковый номер в списке опроса. Необходимое значение: 1.
  • pause_retry, NUMBER - пауза перед повтором опроса (сек.). Необходимое значение: interv(сек.) / (kol_pop_max + 1).

`amr_comm_state (Состояние опроса):

  • n, NUMBER - ID.
  • t, NUMBER - тип устройства: 1 - ПУ; 2 - УСПД; 4 - ТО.
  • tm, DATE (формат: 2026-02-20 06:06:53) - время последнего опроса.
  • placeid, NUMBER - ID ТО.
  • st, NUMBER (0|1) - состояние соединения: 0 - нет; 1 - да.
  • stm, DATE (формат: 2026-02-20 06:06:53) - время последнего изменения состояния соединения.
  • cerr, NUMBER - код ошибки соединения (0 - нет ошибки).
  • perr, NUMBER - код ошибки протокола обмена данных (0 - нет ошибки).

evlog_amr (Лог событий опроса):

  • code, NUMBER - ID события. Если для хронологически последнего события code in (120, 136, 223): то к ПУ или УСПД (ident1, ident2) применяется режим опроса: econom.
  • evtime, DATE (формат: 2026-02-20 06:06:53) - время события.
  • ident1, NUMBER - если ident2 = NULL, тогда это ID ПУ, иначе: ID УСПД.
  • ident2, VARCHAR(10) - ID ПУ.

amr_splog (Справочник событий: для расшифровки evlog_amr.code):

  • code, NUMBER - ID события.
  • txt, VARCHAR(100) - название события

gr_kon (Привязка ПУ к контроллеру): - n_kon — ID УСПД - n_sh — ID ТУ. Роль: Главная таблица для получения списка всех ТУ, принадлежащих конкретному УСПД (usp_ids).
