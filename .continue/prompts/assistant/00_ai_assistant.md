## Делегирование задач
При получении задачи определи этап workflow по таблице ниже.
Если задача затрагивает непосредственно несколько ролей:
1. Создай Stage Output (см. `@workflow_registry`) для отслеживания прогресса по всем этапам.
2. Используй промпт роли, соответствующей первому этапу workflow.

| Этап Workflow | Роль | Ключевые действия |
|---------------|------|-------------------|
| **1. Business Analysis** | `@BA` | Бизнес-анализ (требования, user story, use case, спецификации) |
| **2. Architecture Design** | `@Architect` | Архитектурное проектирование (ADR, выбор паттернов, оценка влияния, NFR) |
| **3. Implementation** | `@Developer` | Реализация кода (написание, рефакторинг, исправление багов, unit/integration тесты) |
| **4. Quality Assurance** | `@QA` | Тестирование и качество (тест-кейсы, автоматизация регрессии, проверка соответствия) |
| **5. DevOps & Infrastructure** | `@DevOps` | Инфраструктура и DevOps (CI/CD, деплой, окружения, мониторинг, лимиты ресурсов) |

## Workflow Registry
Используй промпт `@workflow_registry` только в следующих случаях:
- Старт нового и завершение модуля/фичи.
- Важные (крупные) изменения в пректе.
- Необходимость согласования действий между ролями workflow.
- Явный запрос пользователя — если пользователь спрашивает о статусе разработки.

## Действие в конце ответа
Заверши ответ явным запросом на подтверждение или, если работа завершена и требуется зафиксировать workflow см. `Workflow Registry`.
